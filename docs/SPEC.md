# sphinx-revealjs-mascot 仕様書

本書は初期版の動作・利用者向け設定・既定値・エラー条件の正本とする。サンプルは利用例に限定し、これらの定義を複写しない。
プロジェクトの現状と開発の開始方法は [README.md](../README.md)、依存・Python 要件・検証設定は [pyproject.toml](../pyproject.toml)、依存の固定バージョンは `uv.lock` を正本とする。

## 背景と目的

ブラウザで表示するスライドの上にキャラクターを常駐させ、発表の進行に合わせてリアクションさせることで、プレゼンに演出を加える。
sphinx-revealjs で作成したスライドに組み込める Sphinx 拡張として提供する。

利用者はパッケージをインストールし、`conf.py` の `extensions` に `sphinx_revealjs_mascot` を登録する。
拡張が CSS・JavaScript・画像の組み込みを担当し、テンプレート編集や静的ファイルの手動コピーを不要にする。

## 前提・制約

| 項目 | 内容 |
| --- | --- |
| スライド生成 | Sphinx / sphinx-revealjs / reveal.js |
| 記述形式 | MyST-Parser による Markdown と reStructuredText |
| 開発環境 | Python / uv。具体的な要件は冒頭の正本を参照 |
| キャラクター実装 | 素の HTML / CSS / JavaScript。追加の JavaScript ライブラリを使わない |
| Node.js / npm | 拡張のビルド・利用のためには要求しない。既存の開発ツールの要件は変更しない |

## 機能要件

### 待機モーション（常時）

| ID | 動作 | 実現方法 |
| --- | --- | --- |
| F-01 | 左右にゆっくり揺れる | 足元を支点に回転する CSS アニメーション |
| F-02 | 呼吸しているようにわずかに伸縮する | 足元を基準に縦方向へ微小スケールする CSS アニメーション |
| F-03 | ランダムな間隔でまばたきする | JavaScript で短時間、目閉じ画像に差し替える |

揺れと呼吸は表示中の基本モーションとしてループさせ、周期をずらす。
ランダムなまばたきは `idle` 中だけ行い、リアクション中とウトウト中は停止する。
`idle` に戻ったら、次のまばたきまでのランダムな時間を数え直す。
モーションの細かな値は利用者向け設定に公開せず、実装側で調整する。

### イベントリアクション

| ID | トリガー | 動作 | 検知方法 |
| --- | --- | --- | --- |
| F-11 | 前の位置より先のスライドへ移動 | スライドの指定アクション、指定がなければ既定動作 | `slidechanged` |
| F-12 | fragment の表示 | fragment の指定アクション、指定がなければ既定動作 | `fragmentshown` |
| F-13 | 対象イベントのない状態が設定時間続く | `doze` に入り、眠そうな画像・ゆっくり傾く動き・「Zzz」を表示 | 最終対象イベントからの経過時間 |
| F-14 | ウトウト中に対象イベントが発生 | `wake` を実行した後、`idle` に戻る | F-11 / F-12 / F-15 |
| F-15 | 前のスライドへ戻る、または fragment を非表示にする | 新たな指定・既定アクションを実行しない。ただしウトウト中は F-14 を適用 | `slidechanged` / `fragmenthidden` |

#### 無操作タイマー

最初のスライドを表示した時点から計測を始める。
F-11・F-12・F-15 を対象イベントとし、いずれも発生時に経過時間をリセットする。
マウス移動や、スライド・fragment の状態が変わらないキー入力は対象に含めない。
同じスライドで説明を続けている場合も、対象イベントがなければウトウトする。
設定項目と既定値は [拡張の設定](#extension-configuration) に定義する。

#### リアクションの優先順位 <a id="reaction-priority"></a>

- ウトウト中は `wake` を優先し、復帰のきっかけとなったイベントの指定・既定アクションは省略する。
- 新しいアクションを実行するときは、実行中のリアクションとその完了処理を取り消し、最新のアクションに切り替える。
- 同じアクションが続いた場合も、最初から実行する。
- `wake` の途中でも、新しいアクションを実行するイベントが来たら同じ切り替えルールを適用する。
- 未実行アクションを待ち行列やスタックに保持しない。

### アクションの指定方法

| ID | 方式 | 内容 |
| --- | --- | --- |
| F-21 | 明示指定 | スライドと fragment に専用ディレクティブで指定する |
| F-22 | 既定動作 | 前進によるスライド移動は `jump`、fragment 表示は `wink` |
| F-24 | 指定の優先順位 | 明示指定を既定動作より優先する。状態による例外は [リアクションの優先順位](#reaction-priority) に従う |

#### スライドの設定

`mascot` ディレクティブを、そのスライドの見出し直後に置く。
設定自体はスライドに表示せず、そのスライドに適用する。

| オプション | 内容 | 省略時 |
| --- | --- | --- |
| `action` | 明示指定可能なアクション名 | F-22 に従う |
| `position` | [表示位置とサイズ](#position-and-size) に定義する位置 | `conf.py` の設定に従う |

不明なオプション・不正な値・明示指定できないアクションはビルドエラーとする。

#### fragment の設定

`mascot-fragment` ディレクティブで囲んだ内容を、1つの fragment として扱う。
複数の段落や箇条書きをまとめて囲んだ場合は、まとめて表示する。
別々のタイミングで表示する内容は、それぞれ別のディレクティブで囲む。

指定できるオプションは `action` とし、省略時は F-22 に従う。
表示位置はスライドの設定を使用する。

MyST Markdown と reStructuredText の実際の記述例は [サンプル](#samples) に集約する。

### アクション一覧（初期案）

初期版で扱うアクションは次のとおりとする。

| アクション名 | 内容 | 使用画像 | 明示指定 |
| --- | --- | --- | --- |
| `idle` | 通常の待機状態にする | 通常 | 可 |
| `jump` | 1回跳ねて通常の待機に戻る | 通常 | 可 |
| `wink` | 短時間、両目を閉じて通常の待機に戻る | 目閉じ | 可 |
| `surprise` | 短時間、驚きの表情にして通常の待機に戻る | 驚き | 可 |
| `doze` | ウトウトを継続する | 眠そう | 不可。無操作タイマー専用 |
| `wake` | ハッと起きて通常の待機に戻る | 驚き → 通常 | 不可。復帰処理専用 |

### 表示と非表示の切り替え <a id="visibility-toggle"></a>

設定したキーでキャラクターの表示・非表示を切り替える。
非表示中はアニメーションとタイマーを停止し、リアクションを蓄積しない。

再表示時は現在のスライドの位置設定を適用し、`idle` から再開する。
非表示にする前のリアクションやウトウト状態は引き継がず、無操作タイマーとまばたきの待ち時間を数え直す。

### 表示位置とサイズ <a id="position-and-size"></a>

`conf.py` の位置を全体の既定値とし、`mascot` の `position` が指定されたスライドだけ上書きする。
指定のないスライドでは、直前のスライドの位置を引き継がず、全体の既定値に戻す。
スライドを戻る場合も、移動先の位置設定を適用する。

| 指定形式 | 意味 |
| --- | --- |
| `bottom-right` | 画像の右下を基準に画面右下へ配置 |
| `bottom-left` | 画像の左下を基準に画面左下へ配置 |
| `top-right` | 画像の右上を基準に画面右上へ配置 |
| `top-left` | 画像の左上を基準に画面左上へ配置 |
| `x%, y%` | 画面左上を原点として、画像の中心を画面幅の x%・画面高さの y% の位置へ配置 |

任意座標は各軸 0〜100% とし、書式不正や範囲外の値はビルドエラーにする。
画像の中心を指定するため、画面端付近では画像の一部が画面外に出ることを許容する。
定型位置では画像全体を内側に置き、モーションの見切れを避ける余白を設ける。

サイズは画面幅に対する割合で `conf.py` に設定し、全スライドで共通にする。
スライド・fragment 単位のサイズ変更は提供しない。

#### 向きの自動切り替え <a id="automatic-facing"></a>

適用する表示位置に応じて、キャラクターが画面中央を向くように左右の向きを自動で切り替える。
定型位置と任意座標のどちらにも、次の規則を適用する。

| 表示位置 | 向き |
| --- | --- |
| `top-left` / `bottom-left`、または任意座標の x が 50% 未満 | 右向き |
| `top-right` / `bottom-right`、または任意座標の x が 50% より大きい | 左向き |
| 任意座標の x が 50% ちょうど | 元画像の向き |

初期表示・スライド移動・再表示時に、適用する位置から向きを決める。スライドを戻る場合も同じ規則に従う。
反転は CSS の `scaleX(-1)` でキャラクター画像に適用し、左右別の画像は要求しない。
「Zzz」などの文字・記号は反転せず、読める向きに保つ。

## キャラクター画像の要件

標準キャラクターを拡張に同梱し、画像を用意しなくても利用を始められるようにする。
独自画像を使う場合は、利用者が画像フォルダを指定して一式を差し替える。

### 状態と画像の品質

画像は次の4種類とする。ファイル名で使う `{state}` は、この表の識別子に対応する。

| 状態の識別子 | 画像 |
| --- | --- |
| `normal` | 通常 |
| `blink` | 両目を閉じた状態 |
| `sleepy` | 眠そうな状態 |
| `surprise` | 驚いた状態 |

- 背景透過 PNG とし、全画像で同一キャラクター・同一サイズ・同一の立ち位置に揃える。
- [向きの自動切り替え](#automatic-facing) の基準として、標準画像・独自画像ともに全状態を右向きで揃える。
- 全身を収め、足元を画像の下端に合わせる。
- 基準画像を編集して表情差分を作り、絵柄の一貫性を保つ。
- 揺れ・呼吸・跳ねる・傾く動きは CSS で付け、追加画像を要求しない。
- 「Zzz」などの記号は画像に描き込まず、HTML / CSS で重ねる。

### ファイル名の指定と検証 <a id="image-filename-validation"></a>

画像フォルダ内で、設定された命名形式に従う1セットを検出する。
許可する命名形式は次の3つに限定する。

| 命名形式 | 通常画像の例 |
| --- | --- |
| `{state}.png` | `normal.png` |
| `file-name_{state}.png` | `dog_normal.png` |
| `{state}_file-name.png` | `normal_king.png` |

`file-name` は設定にそのまま記述するプレースホルダーであり、利用者が具体名へ書き換える部分ではない。
実際の共通名はファイルから自動検出し、4種類すべてで一致する必要がある。
接頭辞形式と接尾辞形式を混在させない。

| エラー条件 | メッセージの方針 |
| --- | --- |
| 指定した画像フォルダが存在しない | 対象のフォルダを示してビルドエラー |
| 必要な画像が不足している | 不足している状態やファイル名を示してビルドエラー |
| 共通名が混在し、4種類が揃わない | 「4種類の画像が共通のfile-nameで揃っていません」と候補ファイルを示してビルドエラー |
| 完全なセットが複数ある | 「画像セットが複数見つかりました。フォルダを分けてください」とビルドエラー |

独自画像が不正な場合は標準画像で補完せず、ビルド時に利用者へ知らせる。

### 標準画像の制作・配布

後工程で画像生成 AI を用いて、汎用的なオリジナルキャラクターを制作する。
既存キャラクター・作品・ロゴを参照せず、公開前に類似している点がないか確認する。

同梱画像が AI 生成であることと、保有する権利の範囲でリポジトリの [MIT License](../LICENSE) を適用することを明記する。
この記載により第三者の権利を許諾できるわけではなく、画像の著作物性や権利非侵害を保証するものではない。
制作・公開時には [OpenAI 利用規約](https://openai.com/policies/terms-of-use/) と [文化庁の AI 生成物に関する説明](https://www.bunka.go.jp/seisaku/chosakuken/kaizoku/faq.html) を参照する。

## 構成

### 要素構造

transform の競合を避けるため、位置決めと各モーションの担当要素を分ける。

```text
#chara（画面上の固定位置、クリックを透過）
└─ .anchor（定型位置または画像の中心への基準補正）
   └─ .sway（左右の揺れ）
      └─ .breath（呼吸）
         └─ .react（イベント時のアクション）
            └─ .facing（画像の左右反転）
               └─ img#chara-img（状態画像）
```

キャラクター要素は JavaScript で起動時に生成し、`document.body` に追加する。
文字・記号の要素は `.facing` の外側に置く。

### ディレクトリ構成（案）

本 Workspace の `src/` を使ったパッケージ配置を想定する。
実装時の配置案と利用サンプルの関係は次のとおりとする。

```text
project/
├─ docs/
│  └─ SPEC.md
├─ examples/
│  ├─ conf.py
│  ├─ slides.md
│  └─ fragments.rst
└─ src/
   ├─ sphinx_revealjs_mascot/   # 実装時に作成する拡張パッケージ
   │  └─ static/               # 拡張が配布する CSS・JavaScript・標準画像
   └─ tests/
```

利用側にはスライド本文と `conf.py` を置く。独自画像を使う場合だけ画像フォルダを追加する。
拡張の静的ファイルを利用側で保守する構成にはしない。

### 拡張の設定 <a id="extension-configuration"></a>

以下を初期版の設定 API とする。

| 設定名 | 値・単位 | 既定値 |
| --- | --- | --- |
| `revealjs_mascot_image_dir` | 画像フォルダ。相対パスは `conf.py` の所在を基準に解決 | `None`。標準画像を使用 |
| `revealjs_mascot_image_pattern` | [ファイル名の指定と検証](#image-filename-validation) で定義した命名形式 | `'{state}.png'` |
| `revealjs_mascot_position` | [表示位置とサイズ](#position-and-size) で定義した位置を文字列で指定 | `'bottom-right'` |
| `revealjs_mascot_width` | 画面幅に対する割合を数値で指定。0より大きく100以下 | 実挙動確認で決定 |
| `revealjs_mascot_idle_timeout` | ウトウトに入るまでの秒数。正の数値 | `45` |
| `revealjs_mascot_toggle_key` | 表示切り替えに使う単一の文字キー | `'m'`（M キー） |

### ブラウザへの組み込み

ビルド時にスライド本文を HTML に変換し、ブラウザで使う設定・スライドごとの指定も出力へ埋め込む。
通常のスクリプトとして JavaScript を読み込み、表示中の設定取得に `fetch()` を使わない。
外部ファイルを読み込む ES modules に依存しない。

reveal.js はファイルから直接実行できる形式を提供しているが、本拡張と sphinx-revealjs の組み合わせでの確認は必要となる。
技術的な参照先は [reveal.js の初期化](https://revealjs.com/initialization/) と [MDN の JavaScript 読み込み方法](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/What_is_JavaScript) とする。

## 非機能要件

| ID | 項目 | 内容 |
| --- | --- | --- |
| N-01 | オフライン・直接表示 | ビルド結果の HTML を `file://` で直接開いて動作すること。Web サーバー起動やネットワーク接続を必要とせず、CDN を参照しない |
| N-02 | 性能 | 動きと透明度のアニメーションは transform / opacity で行い、スライド操作を妨げないこと |
| N-03 | 本文との重なり | 利用者が位置設定やスライド本文の配置を調整して回避できること |
| N-04 | 操作への非干渉 | `pointer-events: none` とし、設定した表示切り替えキー以外のスライド操作を妨げないこと |
| N-05 | 画面共有 | ウィンドウ共有・画面共有のどちらでもキャラクターが映ること |
| N-06 | 実行時の依存 | reveal.js 同梱物と本拡張のコード・静的ファイルのみで動作すること |
| N-07 | 退避操作 | [表示と非表示の切り替え](#visibility-toggle) に従い、発表中にキャラクターを非表示にできること |
| N-08 | 検証ブラウザ | デスクトップ版 Chrome・Edge の検証時点の最新安定版を対象とする |
| N-09 | 成果物の持ち運び | HTML・画像・CSS・JavaScript を含むビルド出力フォルダ一式で扱う。HTML 単体への全データ埋め込みは要求しない |
| N-10 | 第三者ライセンス | ライセンス原文・表示の保持と配布は [ライセンスの扱い](../third_party/README.md) に従う |

- 標準画像で、表示幅の既定値・定型位置の余白・揺れや呼吸の周期と振れ幅・まばたきの間隔と長さ・リアクションの長さを調整する。
- 任意座標の端付近での表示と、実際の投影・画面共有での見え方を確認する。

## 開発の進め方（案）

1. 本仕様とサンプルソースを整える。
2. 必要な依存追加とパッケージ設定の変更を確認したうえで、拡張を実装する。
3. ダミー画像で機能要件を確認する。
4. 標準画像を制作・同梱し、未確定の表示・モーション値を調整する。
5. サンプルをビルドし、非機能要件を含めたブラウザ確認と投影・共有確認を行う。

サンプルの `conf.py` は形式間で共用し、拡張の既定値をそのまま使用する。

次は拡張本体と必要な依存が導入された後に使う予定のビルドコマンドであり、現段階のビルド成功を示すものではない。

```shell
uv run sphinx-build -b revealjs examples examples/_build/revealjs
```

出力内の `slides.html` と `fragments.html` を、それぞれ対象ブラウザで直接開いて確認する。
