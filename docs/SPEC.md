# sphinx-revealjs-mascot 仕様書

## 1. 背景と目的

ブラウザで表示するスライドの上にキャラクターを常駐させ、発表の進行に合わせてリアクションさせることで、プレゼンに演出を加える。  
sphinx-revealjs で作成したスライドに組み込める Sphinx 拡張として提供する。

## 2. 前提・制約

| 項目 | 内容 |
| --- | --- |
| スライド生成 | sphinx-revealjs |
| 記述形式 | Markdown（MyST-Parser）。reStructuredText にも対応 |
| 開発環境 | Python（uv で依存関係を管理し、ロックファイルで版を固定） |
| 依存しないもの | Node.js / npm |
| キャラクター実装 | 素の HTML / CSS / JavaScript（外部ライブラリなし） |
| キャラクター画像 | 背景透過PNG（画像生成AIでの作成を想定） |
| 実行環境 | ブラウザ（ビルド済みHTMLをローカルで表示） |

設計方針として、依存関係は広く普及し保守が継続している実績あるもの（Sphinx、sphinx-revealjs、reveal.js）に限定し、サプライチェーン上のリスクを抑える。

## 3. 機能要件

### 3.1 待機モーション（常時）

| ID | 動作 | 実現方法 |
| --- | --- | --- |
| F-01 | 左右にゆっくり揺れる | CSSアニメーション（足元を支点に回転、無限ループ） |
| F-02 | 呼吸しているようにわずかに伸縮する | CSSアニメーション（足元基準で縦方向に微小スケール、無限ループ） |
| F-03 | ランダムな間隔でまばたきする | JavaScriptで目閉じ画像へ短時間差し替え（例: 3〜6秒間隔、0.15秒） |

揺れと呼吸は周期をずらし、単調な繰り返しに見えないようにする。

### 3.2 イベントリアクション

| ID | トリガー | 動作（例） | 検知方法 |
| --- | --- | --- | --- |
| F-11 | スライド遷移 | ジャンプ等、スライドごとに指定したアクション | reveal.js の `slidechanged` イベント |
| F-12 | スライド内の段階表示（fragment） | ウインク、跳ねる等 | reveal.js の `fragmentshown` イベント |
| F-13 | 一定時間操作がない | ウトウトする（眠そうな画像＋ゆっくり傾く＋「Zzz」表示） | 最終イベントからの経過時間をタイマーで監視 |
| F-14 | ウトウト中にイベント発生 | ハッと起きる演出の後、通常状態へ戻る | F-11 / F-12 のイベント |

### 3.3 アクションの指定方法

| ID | 方式 | 内容 |
| --- | --- | --- |
| F-21 | 事前設定 | スライド（セクション）ごとに属性でアクションを指定する（例: `data-act="jump"`） |
| F-22 | 既定動作 | 指定がないスライドでは既定のアクションを行う |
| F-23 | LLMによる判定（任意） | ビルド前にスライド本文をLLMへ渡し、アクション候補リストから選ばせて結果をJSONに保存する。本番中はJSONを読むだけとし、LLMを呼び出さない |
| F-24 | 優先順位 | 事前設定（F-21）＞ LLM判定（F-23）＞ 既定動作（F-22） |

### 3.4 アクション一覧（初期案）

| アクション名 | 内容 | 使用画像 |
| --- | --- | --- |
| `idle` | 通常の待機 | 通常 |
| `jump` | 1回跳ねる | 通常 |
| `wink` | ウインクする | 目閉じ（または片目閉じ） |
| `surprise` | 驚く | 驚き |
| `doze` | ウトウトする | 眠そう |
| `wake` | ハッと起きる | 驚き → 通常 |

## 4. キャラクター画像の要件

- 状態画像は最小限とする: 通常、目閉じ、眠そう、驚き の3〜4枚程度。
- 動き（揺れ、呼吸、跳ねる、傾く）はCSSで付け、画像を増やさない。
- 全画像で同一キャラクター・同一サイズ・同一の立ち位置に揃える。差分は基準画像を編集させて作り、一貫性を保つ。
- 構図は全身とし、足元を画像の下端に合わせる（CSSアニメーションの支点を足元に置くため）。
- 背景透過PNGとする。
- 「Zzz」や汗マークなどの記号は画像に描き込まず、HTML/CSSで重ねる。
- 既存の有名キャラクターに似せず、オリジナルのキャラクターとする。

## 5. 構成

### 5.1 要素構造

transform の競合を避けるため、動きごとに要素を入れ子にする。

```txt
#chara（画面右下に固定、クリックを透過）
└─ .sway（左右の揺れ）
   └─ .breath（呼吸）
      └─ .react（イベント時のアクション）
         └─ img#chara-img（状態画像）
```

キャラクター要素はJavaScriptで起動時に生成して `document.body` に追加し、テンプレートの編集を不要にする。

### 5.2 ディレクトリ構成（案）

```txt
project/
├─ pyproject.toml / uv.lock
├─ conf.py                 # sphinx-revealjs の設定、CSS/JSの読み込み指定
├─ index.md                # スライド本文（MyST Markdown）
├─ _static/
│  ├─ chara/
│  │  ├─ normal.png
│  │  ├─ blink.png
│  │  ├─ sleepy.png
│  │  └─ surprise.png
│  ├─ chara.css            # 待機モーション、リアクションのアニメーション
│  ├─ chara.js             # イベント処理、まばたき、ウトウトタイマー
│  └─ actions.json         # LLM判定結果（F-23を使う場合のみ）
└─ tools/
   └─ judge_actions.py     # LLM判定スクリプト（F-23を使う場合のみ）
```

## 6. 非機能要件

| ID | 項目 | 内容 |
| --- | --- | --- |
| N-01 | オフライン動作 | 本番中はネットワークに依存しない。reveal.js はパッケージ同梱のものを使い、CDNを参照しない |
| N-02 | 性能 | アニメーションは transform / opacity のみで行い、スライド操作の妨げにならないこと |
| N-03 | 表示位置 | スライド本文に重ならない位置（初期案: 右下）に表示する。サイズは画面幅に対する比率で指定する |
| N-04 | 操作への非干渉 | キャラクター要素はクリック・キー操作を妨げない（`pointer-events: none`） |
| N-05 | 画面共有 | スライドと同じページ内に描画するため、ウィンドウ共有・画面共有のどちらでも映ること |
| N-06 | 依存関係 | 実行時に読み込むのは reveal.js 同梱物と自作コードのみとする |
| N-07 | 有効/無効の切替 | キー操作またはURLパラメータでキャラクターの表示を切り替えられること（本番トラブル時の退避用） |

## 7. 未確定事項

- ウトウトに入るまでの時間（初期案: 同一スライドで60秒）
- 待機モーションの周期と振れ幅の最終値（実画像で調整）
- F-23（LLM判定）を採用するか。採用する場合の利用LLMと、APIキーの管理方法
- 使用する sphinx-revealjs のバージョンと、CSS/JS追加用の設定項目名（`revealjs_static_path`、`revealjs_css_files`、`revealjs_js_files` 等）の確認
- MyST Markdown でセクションに独自属性（`data-act`）を付ける具体的な書式の確認
- 発表者ノート画面（スピーカービュー）にキャラクターを表示するかどうか

## 8. 開発の進め方（案）

1. ダミー画像で最小構成を作る（待機モーション、まばたき、遷移でジャンプ、fragmentでウインク、ウトウト）。
2. 画像生成AIでキャラクター画像を作成し、差し替えて動きを調整する。
3. スライドごとのアクション指定を入れる。
4. 必要に応じてLLM判定（F-23）を追加する。
5. 実際の投影環境（プロジェクター・画面共有）で表示を確認し、表示位置とサイズの既定値を確定する。
