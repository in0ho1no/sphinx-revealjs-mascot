# 初期版の実装・検証記録

## 実装状態

初期版の拡張本体、ディレクティブ、モーション、状態遷移、配布パッケージ化は実装済みである。
標準画像の表示幅・余白・モーションは Chrome・Edge で確認し、現在の実装値を初版の既定値としている。

動作・設定・エラー条件は [仕様書](SPEC.md)、環境構築・ビルド・確認手順は [README](../README.md) を正本とする。
依存と配布設定は [pyproject.toml](../pyproject.toml)、固定版は [uv.lock](../uv.lock)、作業規約は [AGENTS.md](../AGENTS.md) を参照する。
本書には保守時に必要な設計判断と、検証範囲を記録する。

## 設計判断と再発防止

### Python・JavaScript・CSS の定義を揃える

アクション名・画像状態・既定動作・モーション値を別々に保守すると、追加・変更時に対応が崩れる。
[config.py](../src/sphinx_revealjs_mascot/config.py) の定義を HTML 経由でブラウザへ渡し、JavaScript やサンプルへ既定値を複写しない。
位置の正規化と向きの判定も Python 側に集約する。

[test_mascot_contract.py](../src/tests/test_mascot_contract.py) は、アクション・画像状態・CSS セレクターとモーション変数の対応を検証する。
JavaScript テストにも同じ Python の実定義を渡す。

### JavaScript テストを通常の検証から実行する

JavaScript テストが pytest・CI に接続されておらず、通常の検証だけでは実行されない状態があった。
[test_mascot_runtime.py](../src/tests/test_mascot_runtime.py) から Node.js のテストを起動し、[Tests](../.github/workflows/tests.yml) も pytest を実行する構成にした。
TAP の集計でテストが 0 件でなく、すべて成功したことを確認する。Node.js がない場合や固定版と異なる場合も、スキップせず失敗にする。

[test_mascot_runtime.cjs](../src/tests/test_mascot_runtime.cjs) は DOM・reveal.js・時計を模した状態遷移テストである。
ブラウザの描画や実操作の確認を代替しない。

### 開発ツールが使う実行環境を固定する

pyright の Node.js 自動取得や過去の nodeenv キャッシュにより、管理外の Node.js が選ばれる場合があった。
Node.js は [mise.toml](../mise.toml) で固定し、nodeenv は依存から除外している。
PATH と古いキャッシュの確認手順は README、静的解析の手順は [sk-python-quality](../.agents/skills/sk-python-quality/SKILL.md) を参照する。
PATH が不足している場合に、pyright が案内する `pyright[nodejs]` の追加で対処しない。

CI と手元で Python の系列が異なる状態もあった。
[.python-version](../.python-version) と静的解析の対象バージョンを揃えて維持する。

### テスト探索に必要なパッケージマーカーを残す

[src/__init__.py](../src/__init__.py) を削除した際、pytest がリポジトリルートを import パスへ含めなくなり、`scripts` の import でテスト収集に失敗した。
このファイルはテスト探索に必要なパッケージマーカーとして残し、テンプレート向けの説明だけを実際の役割に合わせて更新した。
削除可否は本文や明示的な参照の有無だけで判断せず、通常の `uv run pytest` でテスト収集を確認する。

### リアクションの切り替えで古い処理を残さない

不正なアクションは状態とタイマーを変更する前に無視する。
新しいアクションを開始するときは、まばたきと以前のリアクションの完了処理を取り消す。
同じアクションの連続指定でも CSS アニメーションを再始動する。

JavaScript テストでは、不正な指定がまばたき・完了処理を壊さないことと、古い完了処理が新しいリアクションへ割り込まないことを検証する。

### 余白と傾きを画像の寸法・向きに合わせる

上端余白を画面高さ基準、跳躍量を画像高さ基準で扱っていたため、条件によって上端で画像が見切れる問題があった。
画像の描画寸法と各モーション・「Zzz」の最大変位から余白を計算し、指定幅で収まらない場合は全スライド共通の上限を適用するよう修正した。
画像ロード・リサイズ・再表示時にも再計算する。
JavaScript テストでは複数の画面比率・画像比率・表示幅で四隅の境界を検証する。

`doze` の傾きを時計回りに固定していたため、左右の配置で傾く方向が非対称だった。
`doze` と `wake` の回転は画像の向きに連動させた。文字・記号は画像の左右反転要素の外に置く。
両方向の回転での境界と、反転要素の外側にある「Zzz」を JavaScript テストで検証する。

### 画像・通知の原本と配布物を分ける

標準画像の原本は `examples/_static/mascot/joubitaki/`、第三者通知の原本は `third_party/` に置く。
Hatchling と拡張のビルド処理で配布物・HTML へ取り込み、複製したファイルを手作業で保守しない。
画像説明書を Sphinx の原稿として検出しないよう、サンプルの `_static` は原稿の対象から除外している。

ライセンス通知は HTML に同梱する素材を対象とし、ビルド環境の Python 推移依存全体を収集する構成へ戻さない。
[notices.py](../src/sphinx_revealjs_mascot/notices.py) に検証・コピーを集約し、素材提供元の版と通知のハッシュを確認する。
詳細は [ライセンスの扱い](../third_party/README.md)、配布物の内容と原本との一致は [test_distribution.py](../src/tests/test_distribution.py) を参照する。

## 検証範囲

### 自動検証

| 対象 | 検証内容 |
| --- | --- |
| 設定・ディレクティブ | 画像セット・設定値の異常系、MyST Markdown と reStructuredText のスライド属性・fragment のまとまり |
| HTML 出力 | `revealjs`・`dirrevealjs`、下位ページを含むローカルリソース参照、画像・通知の同梱 |
| ブラウザ用スクリプト | 準備待ち、位置・向き、まばたき、リアクション、ウトウト・復帰、表示切り替え、レイアウト境界 |
| 配布物 | wheel・ソース配布物の作成と内容、展開した wheel を使う標準画像・独自画像の Sphinx ビルド |
| 品質・開発環境 | ruff・mypy・pyright、AI 設定の参照・フック検査、ライセンス通知の検証 |

サンプル全体は `sphinx-build -E -W -b revealjs` でビルドを確認している。
pytest では `sphinx-revealjs` 内部の非推奨 API 使用による警告がある。
実行コマンドは README と各検証手順を参照し、結果は対象コミットの CI または実行時の出力で確認する。

Node.js 公開版一覧の取得と比較は CI で成功している。更新 Issue の作成・更新の実運用は未確認である。

### ブラウザでの確認

HTML の直接表示、右下への表示、左右反転、スライドごとの位置上書きと既定位置への復帰は、利用者による確認済みである。
2026-10-25 に報告されたブラウザ別の確認範囲は次のとおりである。

| 対象 | Google Chrome | Microsoft Edge |
| --- | --- | --- |
| `positions.html` の `file://` での直接表示 | 確認済み | 確認済み |
| 標準画像の表示幅・余白・モーション | 問題なしとの報告 | 問題なしとの報告 |

### 未確認範囲

- fragment のまとまり、戻る操作、表示切り替えキー、CSS アニメーションの再始動・停止を含む操作全体のブラウザ確認。
- 任意座標の端付近や、横長画面・幅を増やした条件での実描画。
- 実行時のネットワーク要求、実際の投影・ウィンドウ共有・画面共有。
- 別の仮想環境へ wheel をインストールして利用する検証。配布テストは wheel の展開先からの実行である。
