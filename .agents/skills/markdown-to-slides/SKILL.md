# Markdown のスライド化

## 対象と参照資料

元の Markdown と、指定された出力形式・納品先を確認する。本文がなければ提供を依頼し、内容を推測して作り始めない。
出力形式が未指定で、既存プロジェクトからも判断できない場合は確認する。

- `sphinx-revealjs` で作成する場合は、作成前に [記法と作成手順](references/sphinx-revealjs.md) を読む。
- `sphinx-revealjs-mascot` を利用する場合は、作成前に [キャラクター拡張の使い方](references/mascot.md) も読む。
- `sphinx-revealjs` と本拡張を組み合わせて新規作成する場合は、[雛形](assets/starter/) を作業先へコピーして使う。既存プロジェクトでは必要な設定とスタイルだけを取り入れる。
- その他の形式では、以下の共通方針を適用し、その形式で利用できる作成・検証方法を使う。

## 基本方針

- スライドに載せる事実・数値・主張・結論の情報源は、元の Markdown のみとする。記法・設定・描画方法は参照資料を利用できる。
- 内容と話の順序を保つ。条件、例外、単位、出典、比較対象を落とさず、断定の強さを変えない。
- 文字の短縮や図表化は、意味を変えない範囲に限る。元資料にない説明・因果関係・結論を補わない。
- 雛形の例文は元資料の内容に置き換え、発表内容として残さない。
- 明確なルールで判断できる事項は確認せず進める。内容の矛盾や意味の確定が必要な箇所だけを確認する。

## スライドへの変換

- 見出しをもとに分割し、タイトルは元の見出しを優先する。長い節は順序を保って複数枚に分け、元の見出しと続きであることが分かる名前を付ける。
- 1枚で扱う話題は1つにする。箇条書きは3項目程度、各項目は1行を目安とし、意味の保持と読みやすさを優先する。
- 本文は24pt以上を基準とする。HTML では参照資料の CSS 上の換算と表示倍率を踏まえて確認する。
- 収まらない場合は文字を小さくせず、スライドを分割する。長いコード・表も、対応関係と読む順序を保って分ける。
- 補足説明は対応するスライドの発表者ノートへ移せる。ただし、主張を理解するための条件・根拠・結論はスライド上に残す。
- 元資料の実質的な内容は、スライドまたはノートに保持する。目次の重複や装飾など、意味を持たない要素だけを省略できる。
- ノートを利用できない形式では、補足用のスライドとして元の位置に続けて配置する。

## 図表

- 手順はフロー図、構造はブロック図を候補とする。元資料に順序や包含・接続関係が明示されている場合だけ図にする。
- 比較は表、数値の推移は折れ線グラフ、数値の比較は棒グラフを候補とする。図表より文章が明快な場合は文章を使う。
- 数値、単位、軸、凡例、出典を保持する。欠けている値を推測して補間しない。
- 文字を含む図は、画像生成ではなく図形または SVG で作る。出力形式で利用できる方法を選び、文字の可読性も検査する。

## デザイン

- 日本語フォントと日本語の言語設定を明示する。利用環境にそのフォントがあることを確認し、外部フォントの取得を前提にしない。
- 色は背景・文字・強調の3種類を基本とし、必要な場合だけ警告用の1色を追加する。既存の画像やコードの構文強調は別途可読性を確認する。
- 強調色は各スライドの最重要箇所に使う。文字と背景のコントラスト比は4.5:1以上にする。
- キャラクターを使う場合は、画像とモーションの領域を考慮して本文・図表の余白を確保する。

## 完成前の検査

1. 出力形式に応じたビルドまたは生成を実行し、エラー・警告を解消する。
2. 全スライドを画像として書き出すか、ブラウザで各スライドのスクリーンショットを取得して確認する。fragment は表示途中と全表示の状態も確認する。
3. 文字・図表・キャラクターのはみ出し、重なり、不自然な空白を修正する。
4. フォントの置換、意図しない中国語の文字・字形、文字サイズ、色数、コントラストを確認する。元資料の引用など、意図した表記は保持する。
5. 元の Markdown とスライド・ノートを照合し、抜け漏れ、順序、数値、意味の変化を確認する。
6. 段階表示、ノート、キャラクターなど、画像だけで判断できない機能を実際に操作する。
7. 修正した箇所とその影響範囲を再検査し、問題が残らないことを確認する。

描画・操作を確認できる手段がない場合は、実施できた検査まで進め、未検証の項目と制約を報告する。未検証の状態を完成・検証済みと扱わない。

## 完了報告

- 編集可能なソースと、利用に必要なファイルを含む完成した成果物を渡す。
- 省略した要素、ノートへ移した内容、判断に迷った箇所、未検証・未解決の事項があれば簡潔に報告する。
